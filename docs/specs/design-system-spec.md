| 字段较多、配置复杂或需要连续查看 / 编辑    | 使用抽屉                                                           |


## 1. 设计总则

### 1.1 设计目标

B 端后台页面应服务于高频操作、信息判断和任务处理。页面设计应保持克制、规整、可扫读，使用户能够快速识别当前位置、理解数据状态、完成关键操作。


| 目标   | 要求                                    |
| ---- | ------------------------------------- |
| 任务效率 | 主任务清晰，操作入口稳定，用户可快速完成查询、录入、审批、配置、处置等动作 |
| 信息判断 | 重要信息优先展示，状态、风险、异常和结果有明确语义             |
| 页面一致 | 同类页面使用统一框架、统一间距、统一色彩语义和统一交互反馈         |
| 可扩展  | 页面结构支持字段增加、表格列增加、筛选条件增加、状态扩展和权限差异     |
| 可落地  | 关键尺寸、间距、字号、色 token、状态和交互均有明确规范        |


### 1.2 信息层级

页面应按用户任务优先级建立信息层级。


| 层级  | 内容                  | 设计要求                  |
| --- | ------------------- | --------------------- |
| P0  | 当前页面主任务、关键对象、主要操作   | 在核心容器或首屏工作区清晰呈现 |
| P1  | 主要数据、主要表单、主要流程      | 占据页面主要空间，保证可读、可操作、可反馈 |
| P2  | 辅助筛选、说明、次级操作、关联信息   | 与主任务保持清晰关系，视觉强度低于 P1  |
| P3  | 低频配置、更多操作、历史记录、提示信息 | 可通过折叠、抽屉、弹层或次级区域承载    |


### 1.3 一致性要求

- 同一系统内，同类页面应保持相同页面骨架、容器层级、标题位置和操作位置。
- 同一页面内，相同类型模块应使用相同内边距、圆角、间距、标题样式和状态反馈。
- 同一业务字段在列表、详情、表单、图表、对话框中出现时，应保持一致的命名、色彩语义和展示强度。
- 页面应以真实业务信息和真实操作路径组织，并形成完整任务闭环。

## 2. 内容区域结构规范

### 2.1 标准业务内容区

业务页面采用稳定的内容区层级：

```text
→ 内容容器
   → 业务子容器 / 业务模块
```


| 区域              | 定义                          | 设计要求                                        |
| --------------- | --------------------------- | ------------------------------------------- |
| 内容容器            | 背景 `gray-3`，内边距 16px        | 承载页面业务内容，形成页面背景层                            |
| 业务子容器           | 背景 `gray-1`，内边距 24px，圆角 8px | 承载表格、表单、详情、图表、指标等业务模块                       |


### 2.2 业务内容区组织

业务内容区应按照“内容容器 → 业务子容器 / 业务模块”组织，滚动归属按页面类型明确。


| 模块    | 要求                                              |
| ----- | ----------------------------------------------- |
| 内容容器  | 铺满主内容区剩余空间，使用 `gray-3` 背景，内边距 16px              |
| 业务子容器 | 使用 `gray-1` 背景、24px 内边距、8px 圆角；同级容器之间保持 16px 间距 |
| 页面滚动  | 页面内容超出可视高度时，滚动归属应明确；复杂表格优先让表格内容区滚动              |


### 2.3 对话框与抽屉

对话框和抽屉属于内容弹层，用于确认、补充录入、详情查看、轻量编辑和局部配置。


| 类型  | 适用场景                     | 尺寸与结构                              |
| --- | ------------------------ | ---------------------------------- |
| 对话框 | 高风险确认、少量配置、简单补充信息        | 居中展示，有明确标题、关闭入口、内容区和底部操作区；主要承载少量信息 |
| 抽屉  | 详情查看、较多字段编辑、复杂配置、上下文连续操作 | 抽屉默认右侧滑出，标题区固定顶部，内容区可滚动；表单抽屉存在底部操作区，底部操作区固定展示，详情抽屉无需底部操作区。

对话框主要承载少量信息和短流程操作。当内容较多、配置项较复杂、需要滚动阅读或需要连续查看 / 编辑时，应使用抽屉承载内容。抽屉宽度统一使用 560px、880px 或 80% 屏幕宽度自适应，并按内容复杂度选择。


| 抽屉宽度        | 适用场景                     | 空间与内容要求                          |
| ----------- | ------------------------ | -------------------------------- |
| 560px       | 轻量详情、简单编辑、少量补充配置         | 简单配置，无需过多横向空间                    |
| 880px       | 多分组信息、中等复杂表单、需要分区阅读的配置   | 需要较多横向空间，比如有关联表格，大量明细内容          |
| 80% 屏幕宽度自适应 | 复杂详情、复杂配置、关联表格、字段与明细混合查看 | 复杂、多步骤，需要较多横向空间，或包含关联表格 / 大量明细内容 |


字段数按当前抽屉内可见字段估算。内容包含普通表格、少量复合组件或需要中等横向空间时，优先使用 880px 抽屉；表格列较多、关联内容较多、包含左右对照信息或需要多区域展示时，使用 80% 屏幕宽度动态抽屉；配置链路较长或内容区域复杂时，可使用子页面。

#### 抽屉层级要求

- 抽屉属于页面级顶层弹层，打开后应覆盖当前可视区域和底层业务内容。
- 抽屉遮罩层颜色应遵循 [6.8 对话框（Modal）、抽屉（Drawer）、全局提示（Message）、通知提醒框（Notification）、警告提示（Alert）](#68-对话框modal抽屉drawer全局提示message通知提醒框notification警告提示alert) 中的全局遮罩规则。
- 右侧抽屉本体及遮罩层层级应高于 sticky 表头、左右固定列、下拉菜单、文字提示（Tooltip）和页面内其他业务浮层；其层级应高于页面内业务浮层，并避免被表格 sticky 区、下拉菜单或 Tooltip 遮挡。
- 当业务允许从抽屉内继续打开上层抽屉时，应形成清晰的多层抽屉关系。若上层抽屉与下层抽屉宽度相同，下层抽屉应在上层抽屉宽度基础上向左偏移 80px，使下层抽屉左侧边缘可见，用于辅助识别当前抽屉层级。
- 抽屉打开后，底层页面不响应点击、滚动、快捷键或其他业务操作；滚动归属仅保留在抽屉内容区或抽屉内部组件。

## 3. 间距与布局规范

### 3.1 基础单位


| 项目     | 规范                          |
| ------ | --------------------------- |
| 最小原子单位 | 4px                         |
| 间距计算   | `间距 = x × 4px`              |
| 栅格体系   | 12 栅格                       |
| 默认设计画板 | 1440px                      |
| 主流适配宽度 | 1920px、1440px、1366px、1280px |
| 页面最小宽度 | 768px                       |


### 3.2 常用间距


| 场景                   | 间距                                                                   |
| -------------------- | -------------------------------------------------------------------- |
| 内容容器内边距              | 16px                                                                 |
| 常规业务容器内边距            | 24px                                                                 |
| 同级业务容器间距             | 16px                                                                 |
| 列表页联动搜索容器与列表容器间距     | 12px                                                                 |
| 列表页同一容器内搜索区与表格区间距    | 16px                                                                 |
| 列表页联动基础数据统计卡片区与工具栏间距 | 24px                                                                 |
| 工具栏与表格主体间距           | 16px                                                                 |
| 表格主体与分页区间距           | 8px                                                                  |
| 搜索项横向间距              | 32px                                                                 |
| 搜索项纵向间距              | 16px                                                                 |
| 搜索项标签与控件间距           | 8px                                                                  |
| 按钮组内按钮间距             | 8px                                                                  |
| 模块标题与内容间距            | 默认 16px；二级模块与内容之间可用 12px，表达模块层级亲疏；标题下方有一行注解文字时可用 8px，表示注解是对当前标题的补充说明 |
| 表单字段与分组纵向间距          | 同一分组内字段或内容块之间为 20px；不同二级分组之间为 32px；不同一级分组之间为 40px                    |


### 3.3 栅格与响应式


| 视窗宽度           | 栅格列数 | Gutter | Margin | 业务内容区策略                        |
| -------------- | ---- | ------ | ------ | ------------------------------ |
| `< 768px`      | 4    | 16px   | 24px   | 进入最小宽度策略，业务内容保持可读并按页面类型横向滚动或堆叠 |
| `768px–991px`  | 8    | 16px   | 24px   | 业务模块优先单列或两列组织，保持主要操作可见         |
| `992px–1199px` | 12   | 24px   | 24px   | 支持 12 栅格内容布局，复杂列表可声明最小内容宽度     |
| `≥ 1200px`     | 12   | 24px   | 24px   | 业务内容区自适应铺满，列表、表单、图表按页面类型组织     |


当内容区低于 768px 时，页面应进入横向滚动策略。复杂列表页、日志页、审计页、认证记录页、资产明细页等高密度数据页面可声明更大的最小内容宽度，常用值为 1200px。

### 3.4 容器布局


| 容器类型    | 背景 Token | 内边距  | 圆角         | 使用场景           |
| ------- | -------- | ---- | ---------- | -------------- |
| 页面内容容器  | `gray-3` | 16px | 0          | 主内容区背景层        |
| 业务容器    | `gray-1` | 24px | 8px        | 表格、表单、详情、图表、指标 |
| 高密度列表容器 | `gray-1` | 24px | 8px        | 搜索、工具栏、表格、分页组合 |
| 对话框内容区  | `gray-1` | 24px | 8px / 12px | 确认、轻量配置        |
| 抽屉内容区   | `gray-1` | 24px | 0          | 详情、编辑、配置       |


业务容器应铺满外部内容容器的可用宽度。同一页面内，搜索区、工具栏、表格、分页和状态内容应在容器安全区内左右对齐。

### 3.5 滚动策略

不同页面类型的滚动归属应按任务方式区分。页面滚动、容器滚动和组件内部滚动需要形成明确边界，使核心信息可读、关键操作可见。


| 页面类型 / 场景               | 滚动要求                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------- |
| 工作台 / Dashboard / 数据概览页 | 页面内容容器可纵向滚动；基础数据统计卡片、图表、待办、排行等模块按栅格自然向下延展                                           |
| 列表页 / 查询结果页             | 搜索区、基础数据统计卡片区、工具栏和分页区保持稳定；页面内容区域和列表容器铺满可用容器；数据溢出由表格内部滚动承接    |
| 列表页表格数据超高               | 表格数据内容区纵向滚动；搜索区、基础数据统计卡片区、工具栏、表头和分页区保持稳定                                            |
| 列表页表格列过多                | 表格主体横向滚动；搜索区、基础数据统计卡片区、工具栏和分页区不参与表格主体横向滚动；表头、多选列 / 首个关键列、尾列操作在表格内部相对冻结 |
| 表单页 / 新增页 / 编辑页         | 页面内容容器可纵向滚动；字段按分组向下延展，提交操作保持清晰可达                                                    |
| 长配置页 / 字段较多的表单页         | 页面提供锚点导航，锚点对应主要分组，支持快速定位和当前位置识别                                                     |
| 详情页                     | 页面内容容器可纵向滚动；摘要区、信息分组、关联列表按内容自然延展                                                    |
| 分步流程页                   | 当前步骤内容区可纵向滚动；步骤导航和底部操作区保持稳定                                                         |
| 对话框轻量内容溢出               | 对话框内容区可保留基础滚动能力，底部操作区保持稳定；当内容较多或需要明显滚动阅读时，使用抽屉承载内容                                  |
| 抽屉内容较多                  | 抽屉内容区可滚动，标题区保持稳定；表单抽屉如存在底部操作区，底部操作区保持稳定。具体结构见 [7.2 表单页 / 新增页 / 编辑页 / 配置页](#72-表单页--新增页--编辑页--配置页) 和 [7.3 详情页](#73-详情页) |
| 页面低于最小内容宽度              | 业务内容容器保持最小可读宽度。列表页由表格主体承接横向滚动，非列表页可按页面最小宽度策略横向滚动                  |


横向和纵向滚动条建议使用 4px 细滚动条，thumb 使用 `gray-10` 15% 透明度，悬停 / 拖动时透明度变为 30%。

### 3.6 页面容器冻结逻辑


| 区域              | 冻结 / 滚动要求                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| 内容容器            | 铺满业务内容区，按页面类型承接页面纵向滚动或固定可用高度；列表页内容容器填满可用空间                                                           |
| 列表页业务容器         | 铺满内容容器可用高度，搜索区、基础数据统计卡片区、工具栏、表头和分页区作为稳定区域，不参与表格主体横向滚动                                                |
| 列表页表格内容区        | 承接纵向数据滚动和横向列滚动；表头、多选列 / 首个关键列、尾列操作在表格内部相对冻结                                                          |
| 表单页内容区          | 抽屉标题区保持稳定；如表单抽屉存在底部操作区，底部操作区保持稳定；内容区承接滚动。                                                                            |
| 对话框 / 抽屉        | 标题区保持稳定，内容区承接滚动；底部操作区按表单、确认和详情场景区分，具体见 [2.3 对话框与抽屉](#23-对话框与抽屉)、[7.2 表单页 / 新增页 / 编辑页 / 配置页](#72-表单页--新增页--编辑页--配置页) 和 [7.3 详情页](#73-详情页) |
| 抽屉打开时           | 作为页面级顶层弹层展示，层级高于内容容器、表格 sticky 区域和其他页面内业务浮层；抽屉打开时应遮挡底层业务内容，并避免底层页面在抽屉操作期间被误触 |

## 4. 字体与排版规范

### 4.1 字体家族

页面应使用系统默认界面字体，保证跨平台可读性。


| 平台      | 推荐字体                                               |
| ------- | -------------------------------------------------- |
| macOS   | `-apple-system`、`BlinkMacSystemFont`、`PingFang SC` |
| Windows | `Segoe UI`、`Microsoft YaHei UI`、`Microsoft YaHei`  |
| 通用兜底    | `Helvetica Neue`、`Arial`、`sans-serif`              |


图表、表格、表单、对话框、抽屉、按钮、标签、提示说明应使用同一字体体系。

### 4.2 字阶与行高


| 类型        | 字号   | 行高   | 字重        | 使用场景                   |
| --------- | ---- | ---- | --------- | ---------------------- |
| 超大标题      | 48px | 54px | 600 / 700 | 大屏标题、品牌主标题、少量视觉主标题     |
| 重点标题      | 28px | 36px | 600 / 700 | 重要报告标题、重点展示标题         |
| 模块标题      | 16px | 26px | 600       | 卡片标题、分区标题、抽屉主标题        |
| 标签页 / 大按钮 | 16px | 28px | 400 / 500 | 重要按钮、标签页标题、业务内容区高优先级操作 |
| 正文        | 14px | 22px | 400       | 表格、表单、普通文本、说明正文        |
| 辅助文本      | 12px | 20px | 400       | 提示、说明、标签、元信息           |
| 高密度表格文本   | 12px | 20px | 400       | 日志、审计记录、密集列表           |


### 4.3 字重使用


| 字重             | 使用要求                 |
| -------------- | -------------------- |
| 400 Regular    | 正文、说明、表单内容、表格内容      |
| 500 Medium     | 导航选中、按钮、重点字段、状态强调    |
| 600 / 700 Bold | 重点标题、模块标题、关键数字、强调信息 |


同一页面建议控制在 3–4 个字号内。高密度列表页和表单页应优先保证文字清晰、轻量、可扫读。标题用于建立结构层级，关键数字可适当强化，辅助文字应保持足够对比度。

### 4.4 文本排版


| 场景   | 要求                                                                 |
| ---- | ------------------------------------------------------------------ |
| 模块标题 | 16px / 26px / 600，表达当前模块内容；与下方内容间距默认 16px，规则见 [3.2 常用间距](#32-常用间距) |
| 表格表头 | 紧凑表格为 12px / 20px / 600，常规表格为 14px / 22px / 600；宽松档按组件映射表执行        |
| 表格正文 | 紧凑表格为 12px / 20px / 400，常规表格为 14px / 22px / 400；宽松档按组件映射表执行        |
| 字段标题 | 字号 14px，字重 400，颜色使用 `gray-8`；同一表单区域内字段标题宽度统一，字段标题区域整体右对齐                                  |
| 辅助说明 | 12px / 20px / 400，位于字段下方或模块说明区域                                    |
| 错误提示 | 说明具体原因和修正方式，位于字段下方                                                 |
| 超长文本 | 表格、详情和普通文本默认单行省略，悬停展示完整内容；表单字段标题限定最多 10 个字，如超过则使用缩写加注解方式展示         |


## 5. 品牌色、中性色、语义色、图表色规范

本章只定义 **色 token 的选用规则**，不写具体色值。具体色值不在本文档中定义，由实现环境中的主题变量提供。

### 5.1 品牌色与语义色分工


| 类型  | Token 系列                                                                                                                                                         | 使用范围                                                                  |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 品牌色 | `p1`–`p10`                                                                                                                                                       | 基础组件皮肤色，如主要按钮、导航选中、聚焦边框、单选 / 多选选中、链接强调；支持多套皮肤切换时仅切换主题色P系列对应的科技绿或科技蓝色彩 |
| 语义色 | `Deep red-1`–`Deep red-10`、`Red-1`–`Red-10`、`Orange red-1`–`Orange red-10`、`Orange-1`–`Orange-10`、`Yellow-1`–`Yellow-10`、`Green-1`–`Green-10`、`Blue-1`–`Blue-10` | 有业务含义的状态、结果、流程、风险、告警、等级信息                                             |
| 中性色 | `gray-1`–`gray-10`                                                                                                                                               | 背景、边框、文本、禁用、分割线等中性界面元素                                                |
| 图表色 | `c-1`–`c-20`                                                                                                                                                     | 普通分类、非语义维度的图表配色                                                       |


有业务语义的信息应使用功能语义色，不使用品牌色 `p` 系列。品牌色不承担成功、失败、警告、进行中等业务含义表达。

### 5.2 品牌主色

品牌主色为P-科技绿和P-科技蓝系列，基准 token 为 `p6`。品牌色仅作为基础组件皮肤色，用于主要按钮、导航选中、聚焦边框、单选 / 多选选中等通用交互样式。


| Token | 使用场景                   |
| ----- | ---------------------- |
| `p1`  | 主色浅背景、focus ring、浅色选中底 |

| `p3`  | 主色中浅、品牌装饰辅助            |
| `p4`  | 主色中间态、品牌装饰辅助           |
| `p5`  | 主要按钮 hover、主色 hover    |
| `p6`  | 主色基准、主要按钮默认、主交互色       |
| `p7`  | 主要按钮 active、点击态、深主色边框  |
| `p8`  | 主色深、强调文本点击态            |
| `p9`  | 主色特深、深色图形化配色           |
| `p10` | 主色最深，少量强调              |



| 场景                 | 使用 Token |
| ------------------ | -------- |
| 主要按钮默认 / 主操作 / 主色  | `p6`     |
| 主要按钮 hover         | `p5`     |
| 主要按钮 active        | `p7`     |
| 主色浅背景 / focus ring | `p1`     |
| 主色强调文本 active      | `p8`     |


### 5.3 中性色

中性色 token 按编号统一管理。同一 token 可在不同区域复用，一个 token 可以覆盖多个界面语义。例如 `gray-3` 既可用于页面内容容器背景，也可用于下拉菜单项 hover 背景。


| Token     | 使用场景                         |
| --------- | ---------------------------- |
| `gray-1`  | 业务容器、卡片背景、对话框内容区             |
| `gray-2`  | 页面浅背景、表格表头背景                 |
| `gray-3`  | 页面内容容器背景、下拉菜单 hover 背景、弱分区背景 |
| `gray-4`  | 分割线、组件边框                     |
| `gray-5`  | 边框、输入框边界、次要按钮边框              |
| `gray-6`  | 禁用态、未知核心语义用色、占位文字如输入框内的引导暗文  |
| `gray-7`  | 次要文字、说明性内容、禁用文字、图标默认颜色       |
| `gray-8`  | 正文                           |
| `gray-9`  | 主要文本、标题、正文重点内容               |
| `gray-10` | -                            |

| 黄       | `Yellow-1`–`Yellow-10`         | 等级语义色          |
| 绿       | `Green-1`–`Green-10`           | 等级语义色、状态语义色    |
| 蓝       | `Blue-1`–`Blue-10`             | 等级语义色、状态语义色、链接 |

## 6. 组件使用规范

### 6.1 组件尺寸

组件尺寸统一使用 `紧凑`、`常规`、`宽松` 三档命名，默认使用 `常规`，即中号。需求未明确指定尺寸时，不得默认使用紧凑或宽松尺寸。


| 尺寸  | 使用场景                 | 落地要求                    |
| --- | -------------------- | ----------------------- |
| 紧凑  | 高密度列表、筛选区、工具栏和有限空间   | 使用组件映射表中紧凑档的真实属性、配置项或样式 |
| 常规  | 常规后台页面、表单、列表和一般操作    | 默认尺寸，使用组件映射表中常规档的真实实现   |
| 宽松  | 重点表单、低密度页面和需要强化操作的区域 | 使用组件映射表中宽松档的真实属性、配置项或样式 |


组件不支持某个尺寸档位时，应按组件映射表说明执行，不得自行推导 `small / middle / large`、高度、内边距或 class。

### 6.2 按钮（Button）


| 按钮样式类型 | 使用场景                           | 要求                                                                                        |
| ------ | ------------------------------ | ----------------------------------------------------------------------------------------- |
| 主要按钮   | 页面主操作、表单提交、列表新建、流程确认等第一优先级操作   | 用于当前操作区域中最重要、最推荐用户执行的核心操作。同一操作组内通常只保留一个主要按钮，避免多个高权重操作同时出现导致用户判断成本增加                       |
| 次要按钮   | 第二优先级操作，如保存草稿等                 | 用于重要但非核心的推荐操作，视觉权重低于主要按钮。可与主要按钮并列出现，也可在同一操作区域中出现多个，但需保证主次关系清晰                             |
| 辅助按钮   | 取消、导入、导出、筛选、配置、刷新、重置等工具型或辅助型操作 | 用于支撑当前任务的可选操作，通常不直接推动主流程完成。视觉权重应低于主要按钮和次要按钮，避免干扰用户完成核心任务                                  |
| 文字按钮   | 卡片内操作，如编辑、详情、删除等         | 用于局部区域内的单点操作，通常不占用主要操作区空间。可承载编辑、详情等低风险操作，也可承载删除等高风险操作；高风险操作应遵循 [8.6 Confirm](#86-confirm) |


按钮文案应使用明确动词，如 `新建`、`保存`、`提交`、`取消`、`搜索`、`清空`、`导入`、`导出`、`删除`。

按钮默认不使用风险样式，按钮样式类型不决定操作风险等级。删除、禁用等高风险操作可根据所在区域使用对应按钮样式，但无论采用何种按钮样式，均应根据操作影响提供带有影响说明的二次确认，并遵循 [8.6 Confirm](#86-confirm)。

主要、次要、辅助和文字按钮是按钮的样式类型，每种样式均可按业务需要使用以下内容组合：


| 内容组合             | 使用要求                                                 |
| ---------------- | ---------------------------------------------------- |
| 仅文字              | 用于语义明确的常规操作                                          |
| 前置图标 + 文字        | 图标辅助识别操作类型，文字表达完整动作                                  |
| 文字 + 后置图标        | 适合包含展开、跳转或下拉能力的操作                                    |
| 前置图标 + 文字 + 后置图标 | 适合同时表达操作语义和后续菜单能力的复合操作                               |
| 仅图标              | 用于空间有限且语义稳定的工具操作；悬停时必须提供文字提示（Tooltip），并提供 aria-label |


例如“导出”可使用“导出图标 + 导出文字 + 下拉图标”的组合，点击后显示下拉菜单（Dropdown），供用户选择导出格式。按钮内容组合不改变其主要、次要、辅助或文字按钮的样式类型。

### 6.3 输入框（Input）、选择器（Select）、文本域


| 控件        | 要求                                                         |
| --------- | ---------------------------------------------------------- |
| 输入框       | 默认占位文案使用 `请输入...`，可追加业务说明                                  |
| 选择器       | 默认占位文案使用 `请选择...`，支持多选占位文案使用 `请选择，支持多选...`，单选、多选、树选、级联选择适用 |
| 日期 / 时间范围 | 默认占位文案使用 `请选择...`，可按业务展示开始时间 / 结束时间                        |
| 文本域       | 支持多行录入，支持拖拽，可展示字数统计，如 `0/100`                              |


### 6.4 表格（Table）


| 项目      | 要求                                                                            |
| ------- | ----------------------------------------------------------------------------- |
| 表头      | 背景 `gray-2`，文字 `gray-9`，字重 600，纵向滚动时保持稳定                                      |
| 行高      | 紧凑表头和普通行 40px；常规表头和普通行 48px；宽松档按组件映射表执行                                       |
| 单元格     | 紧凑为 12px / 20px / 400 / `gray-8`；常规为 14px / 22px / 400 / `gray-8`；宽松档按组件映射表执行 |
| 空值      | 统一显示 `-`                                                                      |
| 时间      | 使用 `YYYY-MM-DD HH:MM:SS`                                                      |
| 超长文本    | 单行省略，悬停展示完整内容                                                                 |
| 标签组     | 单行省略，省略数量以标签形式显示+n，悬停展示完整标签内容                                                 |
| 行 hover | 行背景使用`gray-3`，文字颜色保持稳定                                                        |
| 多选列     | 默认固定在最左侧                                                                      |
| 关键列     | 表格列较多时，首个关键识别列应保持可见，默认固定在最左侧                                                  |
| 启停状态开关列 | 当操作中有启动、停止操作时，需单独命名为启用状态，单元格使用开关组件，默认固定在最左侧，如有操作则位于操作列左侧                      |
| 操作列     | 默认固定在最右侧；操作数量在 3 个以内时全部直接展示；超过 3 个时，前 2 个直接展示，其余收纳到 `更多`，并展示后置下拉图标。                      |


表格操作列按照操作项数量适应宽度并固定在最右侧。
表格非操作列应按照表格预计显示内容限定最小展示宽度，默认最小展示宽度为 200px，自适应填充表格，如遇以下特定业务列可对应预留最小展示宽度：显示中文用户名称列最小展示宽度为120px、显示IP地址列最小展示宽度为 130px、显示MD5列最小展示宽度为 290px、显示端口号列最小展示宽度为90px、显示等级或状态标签列最小展示宽度为 140px。
表格中的字段应按业务语义拆分为清晰列。姓名 / 工号、资产名 / IP、标题 / 描述等复合信息应拆为独立列，保证排序、筛选、对齐和扫读效率。
当表格列内容为分类、风险等级、状态、组织单位时可增加筛选能力，当表格展示内容为序号、优先级、数量、时间时可增加排序能力。

### 6.5 分页（Pagination）


| 项目   | 要求                 |
| ---- | ------------------ |
| 默认每页 | 20 条               |
| 可选条数 | 10 / 20 / 50 / 100 |
| 总数文案 | `共计 X 条`           |
| 位置   | 位于表格底部，正常数据态展示     |
| 左侧区域 | 可承载跨页全选            |
| 右侧区域 | 承载总数、每页条数、页码轨道和跳页  |


完整分页从左到右依次展示总数、每页条数选择器、页码轨道和跳页输入。页码、上一页和下一页控件统一为 32px；每页条数选择器宽 100px；跳页输入框宽 52px。分页应支持页码切换、每页条数切换和回车跳页，并触发表格刷新。空数据、加载中和异常状态下，分页区按状态规则隐藏或恢复。

### 6.6 标签（Tag）与状态

标签应根据语义优先级选择展示强度。等级类字段按 [标签优先级规则](#标签优先级规则) 选择实色语义标签和浅色语义标签；执行状态、判断结果、置信度使用图标语义标签；普通分类优先使用基础标签或普通文本。

同一页面内，标签颜色、文案、形态应保持一致。同一字段在表格、详情、图表和弹层中出现时，应保持颜色语义一致。


| 标签类型    | 使用场景                | 样式要求                                             |
| ------- | ------------------- | ------------------------------------------------ |
| 实色语义标签  | 当前页面优先级最高、最需要先识别的信息 | 底色使用对应语义色的第6阶，如 `Red-6`；文字色使用中性色 `gray-1`        |
| 浅色语义标签  | 次优先级状态或结果           | 浅底色使用对应语义色的第1阶，如 `Red-1`；文字使用对应语义色的第7阶，如 `Red-7` |
| 图标语义标签  | 解释性状态 / 结果信息        | icon 使用对应语义色的第6阶，如 `Red-6`；文字使用中性色 `gray-8`      |
| 状态点语义标签 | 第三优先级及以下状态、结果、进程    | 圆点使用对应语义色的第6阶，如 `Red-6`；文字使用中性色 `gray-8`         |
| 基础标签    | 分类、类型、普通标签          | 底色使用中性色 `gray-2`，文字使用中性色 `gray-9`                |


无语义的标签使用基础标签，需要辅助提醒表达语义倾向时使用含语义色彩的标签，标签使用时默认优先使用浅色语义标签。

同一页面场景中，如有多个逻辑需要语义表达时，根据信息权重，按照浅色语义标签-图标语义标签-状态点语义标签来进行排序，当有明确风险等级语义时，使用实色语义标签。

同一页面场景，如有多个风险等级时，最多显示 1 个实色语义标签。风险等级类信息按优先级选出 1 个实色语义标签，其余风险等级信息降级使用浅色语义标签；执行状态、判断结果、置信度等过程类信息使用图标语义标签或状态点语义标签展示，可同时存在多个图标语义标签或状态点语义标签。

#### 标签优先级规则

当同一信息组或同一条记录中同时出现多个风险等级字段时，应按字段优先级选择展示强度。命中的第一类等级作为唯一实色语义标签，其余风险等级字段使用浅色语义标签。


| 优先级 | 字段类型        | 固定命名来源                     |
| --- | ----------- | -------------------------- |
| 1   | 告警 - 告警级别   | [5.5 等级语义色映射](#55-等级语义色映射) |
| 2   | 安全事件 - 事件级别 | [5.5 等级语义色映射](#55-等级语义色映射) |
| 3   | 攻击者 - 威胁等级  | [5.5 等级语义色映射](#55-等级语义色映射) |
| 4   | 漏洞等级        | [5.5 等级语义色映射](#55-等级语义色映射) |
| 5   | 脆弱性 - 威胁等级  | [5.5 等级语义色映射](#55-等级语义色映射) |
| 6   | 风险资产 - 风险等级 | [5.5 等级语义色映射](#55-等级语义色映射) |


当同一信息组或同一条记录中同时出现多个执行状态时，研判结果、处置状态、置信度等状态可使用图标语义标签样式展示，也可使用状态点语义标签。


| 状态类型           | 固定命名来源                         | 默认展示                      |
| -------------- | ------------------------------ | ------------------------- |
| 研判结果           | [5.6 状态语义色映射](#56-状态语义色映射)     | 默认使用图标语义标签，需要弱化时使用状态点语义标签 |
| 处置状态           | [5.6 状态语义色映射](#56-状态语义色映射)     | 默认使用图标语义标签，需要弱化时使用状态点语义标签 |
| 置信度            | [5.6 状态语义色映射](#56-状态语义色映射)     | 默认使用图标语义标签，需要弱化时使用状态点语义标签 |
| 流程状态、审批状态、任务状态 | [5.7 三大场景语义色映射](#57-三大场景语义色映射) | 状态点语义标签                   |


### 6.7 卡片（Card）：基础数据统计卡片与统计卡片区

基础数据统计卡片用于在页面顶部集中展示关键业务数据，适用于列表页统计、风险统计、资产概况、运营分析、告警统计、工作台 / Dashboard / 概览页等场景。

当前基础数据统计卡片标准形态为「单一数值指标卡」。不再将多数值指标卡作为标准演示模式；如页面确需展示趋势、小图形、占比或复杂分析信息，应作为图表卡片或分析卡片扩展说明，不作为单一数值指标卡的默认结构。

#### 使用模式

| 模式 | 适用场景 | 要求 |
| --- | --- | --- |
| 列表页模式 A：可点击筛选 | 需要通过指标卡快速筛选页面内容的列表页 | 指标卡作为筛选入口，点击后联动下方表格、列表、图表或数据内容 |
| 列表页模式 B：只读展示 | 指标卡仅展示全局统计数据，不参与当前列表筛选的场景 | 指标卡作为独立统计展示，不支持选中态和 Hover 反馈 |
| Dashboard / 概览页：只读展示 + 支持跳转 | 工作台、Dashboard、概览页中的核心指标入口 | 指标卡展示核心业务指标，可点击跳转到对应业务入口 |

#### 单一数值指标卡结构

```text
单一数值指标卡
├─ 图标
└─ 内容区
   ├─ 标题 + 提示 icon
   └─ 数值 + 单位
```

#### 指标卡组合结构

```text
指标卡组合
├─ 外层容器
└─ 指标卡列表（横向排列）
   ├─ 指标卡
   ├─ 指标卡
   ├─ 指标卡
   └─ 指标卡
```

只读展示模式与 Dashboard / 概览页跳转模式中，指标卡之间增加竖向分割线：

```text
只读指标卡组合
├─ 外层容器
└─ 指标卡列表（横向排列）
   ├─ 指标卡
   ├─ 分割线
   ├─ 指标卡
   ├─ 分割线
   ├─ 指标卡
   ├─ 分割线
   └─ 指标卡
```

#### 整体布局规范

| 属性 | 规范 |
| --- | --- |
| 外层容器背景 | `gray-1` |
| 外层容器圆角 | 8px |
| 外层容器高度 | 104px |
| 外层容器内边距 | 上下 12px，左右 24px |
| 排列方式 | 横向 Flex |
| 垂直对齐 | 居中 |
| 内容溢出 | Hidden |
| 指标卡数量建议 | 4 个优先，最多建议 6 个 |
| 宽度适配 | 跟随页面内容区自适应 |

#### 指标卡基础布局

| 属性 | 规范 |
| --- | --- |
| 指标卡高度 | 80px |
| 指标卡最小宽度 | 240px |
| 指标卡布局 | 图标在左，内容在右 |
| 图标与内容间距 | 8px |
| 内容区布局 | 纵向排列 |
| 标题与数值间距 | 6px |
| 垂直对齐 | 居中 |
| 横向分布 | 等分外层容器 |
| 标题溢出 | 超长省略 |
| 数值展示 | 数值与单位保持完整，不压缩 |

#### 图标规范

基础数据统计卡片中的图标必须使用工程底座提供的三维图标资源，不得自行绘制、生成、拼接或引入新的图片资源。

| 属性 | 规范 |
| --- | --- |
| 图标来源 | 使用工程底座提供的三维图标资源 |
| 图标类型 | 三维图标图片 |
| 图标尺寸 | 64px × 64px |
| 图标位置 | 指标卡左侧 |
| 图标背景 | 不使用额外底色块 |
| 图标适配 | `object-fit: contain` |
| 图标与内容间距 | 8px |

当现有三维图标资源无法精确匹配业务语义时，应优先选择语义最接近的现有资源；确需新增资源时，应先补充到工程底座三维图标库和对应文档后再使用，不得在页面内临时自造图片。

#### 标题与提示说明规范

| 属性 | 规范 |
| --- | --- |
| 标题字号 | 14px |
| 标题颜色 | `gray-8` |
| 标题行高 | 22px |
| 提示 icon 尺寸 | 16px × 16px |
| 提示 icon 颜色 | `gray-7` |
| 标题长度 | 建议 10 字以内，超过后省略显示 |
| 标题与提示 icon 间距 | 4px |

#### 数值与单位规范

| 元素 | 属性 | 规范 |
| --- | --- | --- |
| 主数值 | 字号 | 24px |
| 主数值 | 行高 | 32px |
| 主数值 | 字重 | 700 |
| 主数值 | 颜色 | `gray-9` |
| 主数值 | Hover 变化 | 仅 Dashboard / 概览页跳转模式 Hover 时变为 `p6` |
| 单位 | 字号 | 12px |
| 单位 | 行高 | 20px |
| 单位 | 颜色 | `gray-8` |
| 单位 | 与数值间距 | 4px |
| 单位 | 对齐方式 | 与数值 baseline 对齐 |

#### 可点击筛选模式

| 状态 | 样式规范 |
| --- | --- |
| 默认状态 | 指标卡背景 `gray-1`，1px 透明边框，圆角 8px |
| Hover 状态 | 指标卡背景 `gray-2`，鼠标 Pointer |
| 选中状态 | 背景使用 40% `p1`，边框 1px `p6`，圆角 8px |
| 外层容器 | 保留白底容器、8px 圆角、12px / 24px 内边距 |
| 卡片间距 | 内部指标卡横向间距为 0 |
| 分割线 | 不使用分割线 |
| 点击热区 | 整张指标卡 |
| 选择方式 | 单选，可再次点击取消 |

可点击筛选模式中，指标卡与搜索区筛选条件为 AND 关系；搜索条件和指标卡选中状态共同决定下方数据。默认不选中，点击指标卡后触发数据刷新，切换筛选状态时需要有 Loading 反馈。

#### 只读展示模式

| 属性 | 规范 |
| --- | --- |
| 外层容器 | 白底、8px 圆角、固定 104px 高 |
| 指标卡背景 | 透明 |
| 鼠标样式 | Default |
| Hover | 无反馈 |
| Selected | 不支持 |
| 分割方式 | 使用竖向分割线 |
| 卡片与分割线间距 | 卡片 / 分割线 / 卡片之间均为 12px |

只读展示模式中，指标卡数据为全局统计值，不随当前搜索条件变化，不参与当前表格筛选逻辑；可随页面级全局条件变化，例如全局时间范围。

#### Dashboard / 概览页跳转模式

| 属性 | 规范 |
| --- | --- |
| 外层容器 | 与只读展示模式一致 |
| 指标卡背景 | 透明 |
| 分割方式 | 使用竖向分割线 |
| 鼠标样式 | Pointer |
| Hover 热区 | 整张指标卡 |
| Hover 状态 | 数值颜色变为 `p6` |
| 点击热区 | 整张指标卡 |
| 点击行为 | 打开对应业务入口，建议新页面打开 |
| Selected | 不支持 |

Dashboard / 概览页跳转模式中，指标卡用于展示核心业务指标，不参与筛选逻辑；整张指标卡可点击，点击后打开对应业务入口。该模式适用于核心入口，不用于普通列表页筛选。

#### 分割线规范

分割线仅用于：

1. 列表页模式 B：只读展示；
2. Dashboard / 概览页：只读展示 + 支持跳转。

| 属性 | 规范 |
| --- | --- |
| 宽度 | 1px |
| 高度 | 62px |
| 颜色 | `gray-4` |
| 间距 | 分割线左右与卡片间距均为 12px |
| 位置 | 两张指标卡之间垂直居中 |

可点击筛选模式不使用分割线。

#### 内容规则

1. 当前规范只保留单一数值指标卡。
2. 空值统一展示为 `-`。
3. 空值状态下仍保留图标、标题和卡片结构。
4. 标题建议 10 字以内，超过后省略。
5. 指标数量建议 4 个，最多建议 6 个。
6. 可点击筛选模式必须明确表达筛选含义。
7. 只读展示模式的数据必须为全局统计值。
8. Dashboard / 概览页跳转模式只用于核心指标入口，不用于普通筛选项。
9. 不再定义多数值指标卡作为当前标准模式。
10. 风险、状态、流程类指标应优先使用语义色；普通分类指标使用 `c-1`–`c-20` 分类色 token。

#### 适配规则

1. 指标卡最小宽度为 240px。
2. 指标卡列表横向排列，不换行。
3. 图标、数值、单位不缩小。
4. 内容不足时保持结构稳定。
5. 内容超出时优先减少指标卡数量。
6. 小宽度场景下允许外层容器横向滚动。
7. 标题超长省略，数值与单位保持完整展示。

#### 结果要求

- 指标名称、主数值、单位和提示信息层级清晰。
- 列表页联动指标与搜索条件和表格保持同源。
- 只读展示指标不参与当前列表筛选逻辑。
- Dashboard / 概览页指标可点击时，应有明确 Hover 反馈和跳转目标。
- 基础数据统计卡片区应控制高度和密度，保持表格主体可用。
- 基础数据统计卡片颜色符合语义色和图表色规则。
- 基础数据统计卡片点击、Loading、empty 和跳转反馈应完整呈现。
- 基础数据统计卡片图标遵循本节 [图标规范](#图标规范)。

### 6.8 对话框（Modal）、抽屉（Drawer）、全局提示（Message）、通知提醒框（Notification）、警告提示（Alert）


| 组件                  | 使用要求                                       |
| ------------------- | ------------------------------------------ |
| 对话框（Modal）          | 用于确认、轻量配置和少量信息补充；标题、正文、底部操作区完整；内容较多时转为抽屉承载 |
| 抽屉（Drawer）          | 用于详情、编辑和复杂配置；标题区固定，内容区可滚动；表单抽屉按需固定底部操作区，详情抽屉默认不设置底部操作区。            |
| 全局提示（Message）       | 用于操作成功、处理中等即时反馈                            |
| 通知提醒框（Notification） | 用于操作失败等需要用户持续关注的结果反馈；说明失败原因，不自动消失，需用户手动关闭  |
| 警告提示（Alert）         | 用于页面内持续提示、风险说明、影响范围说明                      |


对话框、抽屉及其他页面级弹层的遮罩层颜色全局统一，使用 `gray-10` 的 30% 透明度，不直接使用具体色值。

高风险保存、删除、停用、覆盖、还原、处置完成等操作应提供二次确认，规则见 [8.6 Confirm](#86-confirm)。保存失败时应保留用户已填写内容，并说明失败原因，反馈规则见 [8.5 Success / Failure](#85-success--failure)。

#### 全局操作反馈规则

所有操作完成后均应给出明确反馈。反馈组件应按操作结果选择，不应只依赖按钮状态或页面数据变化让用户自行判断结果；成功、失败和 Loading 的具体反馈规则见 [8.5 Success / Failure](#85-success--failure)。

如同一操作同时涉及页面刷新、弹层关闭或表格重载，应先保证用户能够感知操作结果，再按业务规则刷新相关数据或关闭当前弹层。

### 6.9 标签页（Tabs）

横向标签页（Tabs）用于同一对象下的并列信息切换；纵向标签页（Tabs）用于长页面的锚点定位，仅触发页面滚动定位，不切换或隐藏页面内容。

### 6.10 图标

图标用于辅助识别，不承担唯一信息表达。图标按钮应提供悬停说明；状态、等级和结果应保留文字。图标密集区域应统一图标尺寸、间距、对齐和选中态。

普通图标应使用既有图标资源体系和语义映射；具体图标选择以 `icon-resources.md` 为准，不得临时编造图标类名、图标来源或与既有资源体系冲突的图标。

数据指标卡片中的业务图标不使用 `static/iconfont.js` 或线性图标作为主视觉图标，必须使用三维图标资源；具体规则见 [6.7 卡片（Card）：基础数据统计卡片与统计卡片区](#67-卡片card基础数据统计卡片与统计卡片区) 的图标规范。

### 6.11 投影


| 层级    | 投影 Token                 | 使用场景                            |
| ----- | ------------------------ | ------------------------------- |
| 一级-向下 | `shadow-1-down`          | 常规卡片、Dashboard 模块、`gray-1` 容器浮起 |
| 二级-向下 | `shadow-2-down`          | 对话框、气泡卡片（Popover）、大型浮层          |
| 二级-向左 | `shadow-2-left`          | 右侧抽屉                            |
| 默认浮层  | `shadow-popover-default` | 下拉面板、标准浮层                       |


卡片浮起优先使用一级投影。对话框、抽屉和浮层应使用二级投影，与页面内容形成明确层级。表格、表单等高密度内容区域应保持轻量层级。

## 7. 页面类型设计规范

### 7.1 列表页 / 查询结果页

#### 页面目标

列表页用于帮助用户筛选、扫读、比较和处理结构化数据。搜索区用于缩小数据范围，表格区是主工作区，二者共同形成可查询、可操作、可反馈的数据闭环。

#### 推荐结构


| 模式   | 适用场景                     | 页面结构                       |
| ---- | ------------------------ | -------------------------- |
| 模式 A | 搜索区 + 联动基础数据统计卡片区 + 表格区  | 搜索区容器；基础数据统计卡片区与表格区合并为列表容器 |
| 模式 B | 非联动基础数据统计卡片区 + 搜索区 + 表格区 | 基础数据统计卡片区容器；搜索区与表格区合并为列表容器 |
| 模式 C | 搜索区 + 表格区                | 搜索区与表格区合并为一个列表容器           |


#### 布局要求

- 列表容器背景为 `gray-1`，内边距 24px，圆角 8px。
- 搜索区、基础数据统计卡片区、工具栏、表格主体、分页区和状态内容应在容器安全区内左右铺满。
- 列表容器按顶部稳定区、表格滚动内容区、底部分页区组织；工具栏和表头属于顶部稳定区，分页属于正常数据态底部稳定区。
- 列表容器内应直接承载搜索区、基础数据统计卡片区、工具栏 / 批量操作区、表格主体、分页区和状态内容。
- 模式 A 中，搜索区容器与基础数据统计卡片表格列表容器间距为 12px；基础数据统计卡片区与工具栏间距为 24px。
- 模式 B 中，基础数据统计卡片区容器与搜索表格列表容器间距为 16px。
- 模式 C 中，搜索区与表格区位于同一列表容器内，间距为 16px。
- 复杂列表页可声明 1200px 最小内容宽度，搜索区、工具栏和分页区保持稳定，表格列溢出由表格主体横向滚动承接。
- 列表页页面内容区域和列表容器应横向、纵向铺满可用容器，内容容器自适应填满主内容区。
- 列表页的数据滚动归属限定在表格内部：纵向滚动由表格数据内容区承接，横向滚动由表格主体承接。
- 纵向滚动时，搜索区、联动基础数据统计卡片区、工具栏、表头和分页区保持稳定；分页区在正常数据态保持在列表容器底部。
- 横向滚动时，搜索区、基础数据统计卡片区、工具栏和分页区不参与表格主体横向滚动；仅表格主体内容横向移动。
- 表格内容多到超过可用高度时，表格主体内容区滚动，分页区吸底稳定；表格内容不足以撑满可用高度时，分页区紧跟表格主体底部。
- Loading、empty、error 等状态内容展示在表格主体内容区内，状态内容不挤占搜索区、基础数据统计卡片区、工具栏或分页区位置。

#### 搜索区要求

- 搜索项采用“标题 + 输入 / 选择控件”结构。
- 标题与控件间距为 8px，搜索项横向间距为 32px，纵向间距为 16px。
- 同一搜索区内，标题使用统一宽度，文字右对齐。
- 4 个及以上搜索项默认使用 4 列栅格；当输入控件、搜索控件宽度低于 180px 时降为 3 列。
- 搜索项少于 4 个时，输入 / 选择控件可使用固定宽度 200px，搜索项按内容宽度靠左排列，无需充满搜索容器。
- 输入类占位文案使用 `请输入...`。当输入格式要求较简单时，可使用暗文提示，如 `请输入 xxxx 格式内容`；当输入格式复杂或需要展示输入示例时，应在字段标题后增加注解图标，悬停字段标题或注解图标时，使用文字提示（Tooltip）展示完整说明。选择类、日期类和时间范围类占位文案使用 `请选择...`；支持多选时使用 `请选择，支持多选...`。
- 搜索项按栅格列线对齐，多行搜索项的标题右边界、控件左边界和控件右边界按列对齐。
- 操作按钮作为搜索表单最后一个操作槽位，视觉顺序为 `搜索` 在左、`清空` 在右。搜索项少于 4 个时，操作按钮跟随搜索项靠左排列；搜索项 4 个及以上时，操作按钮整体右对齐。
- 点击 `搜索` 后按当前筛选条件刷新表格，页码重置到第 1 页，并展示 Loading。
- 点击 `清空` 后只清空搜索区条件，当前列表结果、页码、表头筛选和排序保持当前生效状态。
- 搜索区条件变化后保持待提交状态，点击 `搜索` 后再刷新表格和联动基础数据统计卡片区。
- 高级筛选展开 / 收起时保留已输入条件。

#### 基础数据统计卡片区要求

- 基础数据统计卡片区的组件结构、尺寸、图标、标题、数值、单位、分割线和状态规则按 [6.7 卡片（Card）：基础数据统计卡片与统计卡片区](#67-卡片card基础数据统计卡片与统计卡片区) 执行。
- 模式 A 中，基础数据统计卡片区为可点击筛选模式，应与搜索条件和表格数据同源；搜索条件和指标卡选中状态共同决定下方数据。
- 模式 A 中，指标卡默认不选中，支持单选，可再次点击已选中的指标卡取消筛选。
- 模式 A 中，点击 `搜索` 后，基础数据统计卡片区和表格按当前搜索条件同步刷新。
- 模式 A 中，切换指标卡筛选状态时应刷新下方表格、列表、图表或数据内容，并展示 Loading 反馈。
- 模式 B 中，基础数据统计卡片区为只读展示模式，应作为独立容器置顶，与搜索表格列表容器分离。
- 模式 B 中，指标卡数据为全局统计值，不参与当前表格筛选逻辑；可随页面级全局条件变化，例如全局时间范围。
- 点击 `清空` 后，基础数据统计卡片区保持当前已生效统计口径。
- 表头筛选、表头排序、分页默认只影响表格展示；基础数据统计卡片区统计口径需要联动时，应在页面规则中明确说明。
- 基础数据统计卡片为空时展示轻量 empty 状态，并保持基础数据统计卡片区结构稳定。
- 空间不足时优先缩减基础数据统计卡片数量、压缩指标密度、收起基础数据统计卡片区或触发页面级横向滚动。

#### 工具栏要求

- 工具栏位于表格主体上方，分为左侧操作区和右侧辅助区。
- 左侧承载 `新建`、`导入` 以及依赖勾选项的数据操作。
- 右侧辅助区默认靠右对齐，承载列表全局操作、业务跳转入口、刷新列表和配置表格字段等能力。
- `新建` 位于左侧最前，通常使用主要按钮；同时存在 `新建` 和 `导入` 时，`导入` 使用辅助按钮。
- 未勾选数据时，依赖勾选项的操作按钮进入 disabled 状态，并通过文字提示（Tooltip）说明原因。
- 勾选数据后展示 `已选 N 项`，并恢复导出、启用、停用、删除等操作。
- `配置表格字段`、`刷新列表` 属于固定辅助能力，默认置于右侧辅助区最右侧，使用仅图标辅助按钮，并提供文字提示（Tooltip）。`配置表格字段` 图标使用 `icon-a-shezhixitong`，`刷新列表` 图标使用 `icon-a-shuaxingengxinzhongzhi`。
- 对当前列表生效的全局操作使用辅助文字按钮展示，命名采用“动词 + 范围”的结构，例如 `导出全部`。
- 与当前列表业务强相关的功能入口可使用文字按钮展示；如果在当前页面内打开并可返回当前列表，不追加跳转图标；如果新开标签页、跳转到其他页面或离开当前列表上下文，文字按钮后应追加跳转图标，图标使用 `icon-gengduotiaozhuan`。
- 右侧辅助区同时存在业务入口、全局操作、刷新列表和配置表格字段时，视觉顺序从左到右建议为：业务入口、全局操作、刷新列表、配置表格字段。
- `导出` 默认导出已勾选数据；`导出全部` 默认导出当前已生效搜索条件、表头筛选和排序共同作用后的全部结果。
- 工具栏空间不足时，左侧优先保留 `新建`、`导入` 和 1-2 个高频勾选项操作，其余操作收纳到 `更多`。

#### 表格要求

- 列表页表格默认使用常规尺寸：表头和行高 48px，正文 14px / 22px。明确属于高密度数据场景时可使用紧凑尺寸：表头和行高 40px，正文 12px / 20px。
- 表头背景使用 `gray-2`，表头文字使用 `gray-9`，正文使用 `gray-8`。
- 表格正常数据态展示分页；Loading、empty、error 状态保留表头并隐藏分页。
- Loading 状态替换表格内容区，不保留旧数据行作为遮罩背景。
- 空值统一显示 `-`；时间统一使用 `YYYY-MM-DD HH:MM:SS`。
- 表头和单元格文本单行展示，超长文本单行省略并在悬停时展示完整内容。
- 存在勾选列时，勾选列固定在最左侧，首个关键识别业务列紧随其后并保持可见。
- 存在操作列时，操作列固定在最右侧。
- 表格横向滚动时，表头随列对齐同步滚动；多选列 / 首个关键列保持左侧相对冻结，尾列操作保持右侧相对冻结。
- 横向滚动时，表头与数据列应保持对齐，冻结列阴影只出现在冻结组边界。
- 支持排序的列应展示排序图标，排序状态包括升序、降序、取消排序。
- 支持筛选的列应展示筛选入口，筛选弹层包含筛选项、确定和重置。
- 排序和列筛选完成后刷新表格，页码重置到第 1 页，并展示 Loading。
- 搜索区 `清空` 保持表头筛选和表头排序当前生效状态。
- 表格列应按字段语义拆分展示，复合单元格内容应拆成独立列。
- 行操作数量在 3 个以内时全部直接展示；超过 3 个时，前 2 个直接展示，其余收纳到 `更多`，并展示后置下拉图标。
- 高风险行操作和批量操作应提供二次确认。

#### 分页要求

- 默认每页 20 条，可选 10 / 20 / 50 / 100。
- 分页区右侧展示 `共计 X 条`、每页条数、页码轨道和跳页。
- 支持跨页批量选择时，分页区左侧展示 `跨页全选` 和信息提示图标。
- 跨页全选作用范围为当前已生效搜索条件、表头筛选和排序共同作用后的全部结果。
- 跨页全选复选框左边界与表格勾选列复选框左边界保持对齐。
- Loading、empty、error 状态隐藏分页区；正常非空数据态恢复分页区。

#### 状态要求

- Loading：搜索、基础数据统计卡片刷新、排序、筛选、分页、批量操作期间展示。
- empty：无数据时保留表头，表格内容区展示明确提示。
- error：加载失败时保留表头，展示错误原因和重试入口。
- disabled：无权限或条件不足时禁用，并说明原因。
- success / failure：操作完成后按照 [8.5 Success / Failure](#85-success--failure) 使用全局提示（Message）或通知提醒框（Notification）反馈。
- confirm：删除、停用、覆盖、还原等高风险操作提供确认。
- 初始无数据文案使用 `暂无数据`；搜索无结果文案使用 `暂无匹配数据，请调整筛选条件`。

#### 弹层要求

- 下拉选择、日期选择、列筛选、更多菜单、字段配置和文字提示（Tooltip）应显示在页面最上层可视区域。
- 弹层应根据触发控件自动匹配左对齐或右对齐，靠近屏幕边界时保持完整可见。
- 表格内列筛选、行操作更多菜单、字段配置和文字提示（Tooltip）的层级应高于 sticky 表头、左右固定列和表格滚动容器。
- 行操作更多菜单靠近右侧时右对齐展示。

#### 结果要求

- 页面容器组合符合模式 A / B / C。
- 搜索项标题、控件、按钮按栅格对齐。
- `搜索` 和 `清空` 的行为符合查询联动规则。
- 表格保留关键识别列和操作列可见。
- 排序、筛选、勾选、批量操作、行操作、分页和状态反馈应完整可用。
- 空数据、加载失败和加载中状态均保留表头并给出明确反馈。

### 7.2 表单页 / 新增页 / 编辑页 / 配置页

#### 页面目标

表单页用于信息录入、基础配置、规则配置、审批提交、系统对接和参数设置。表单应让用户明确知道填写目标、字段含义、校验规则、影响范围和提交结果。

#### 推荐结构

```text
→ 对话框 / 抽屉标题区
→ 对话框 / 抽屉内容区
   → 分组标题
   → 说明 / 风险提示
   → 字段区域
→ 对话框 / 抽屉底部操作区
```

#### 布局要求

##### 判断原则

AI 生成表单录入页面时，应优先根据以下因素判断使用哪种容器和布局形式：

1. 录入任务复杂度：轻量录入、常规录入、复杂配置。
2. 录入字段数量：5 个以内、6–12 个、13–20 个、超过 20 个。
3. 组件复杂度：简单组件、复合组件、表格类组件。
4. 字段关系：条件可见、前后步骤强依赖。
5. 操作风险：普通保存、高风险提交。
6. 横向空间需求：是否需要展示表格、复合字段或大宽度内容。

当多个条件同时出现时，应优先满足复杂度更高、风险更高、空间需求更强的场景规则。

##### 表单容器与布局选择规则


| 场景                                        | 推荐组件及布局                                             | 生成要求                                                                |
| ----------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------- |
| 轻量录入：录入项 5 个以内，且主要使用输入框、选择器、开关、单选、多选等简单组件 | 使用宽度 560px 的对话框（Modal），单列纵向表单                       | 适用于创建、编辑、确认类轻量任务。表单控件宽度充满右侧内容区域，不使用双列布局。                            |
| 常规录入：录入项 6–12 个，或存在少量条件可见项、复合录入组件         | 使用宽度 560px 的右侧抽屉（Drawer），单列纵向表单                     | 适用于较完整的配置录入场景。字段按业务顺序纵向排列，控件宽度充满右侧内容区域，不使用双列布局。                     |
| 较多字段录入：录入项 13–20 个，且主要使用简单组件              | 优先使用右侧抽屉（Drawer），按录入维度分组展示                          | 若使用 560px 抽屉，必须采用单列布局；需要提升录入效率时，可使用 880px 抽屉或 80% 屏幕宽度动态抽屉，并采用双列布局。 |
| 大量字段录入：录入项超过 20 个                         | 根据字段依赖关系选择分步流程（Steps）、分区配置、880px 或 80% 屏幕宽度动态抽屉或子页面 | 存在强先后依赖时使用分步流程（Steps）；不存在强先后依赖时，按录入维度分区展示，不因字段数量强制使用分步流程，但建议进行分组。   |
| 录入内容包含表格、复杂复合组件，或需要较大横向展示空间               | 优先使用 880px 右侧抽屉，或 80% 屏幕宽度动态抽屉                      | 表格、复杂复合组件、组合录入区域应独占整行。复杂程度较高、配置链路较长或需要多区域承载时，可使用子页面进行录入。            |
| 字段之间存在条件可见关系                              | 使用条件可见形式                                            | 根据用户已选择或已填写的内容，动态展示后续相关字段。适用于字段之间存在轻度依赖，但不影响整体配置流程顺序的场景。            |
| 多组组合录入字段之间存在明确先后依赖关系                      | 使用分步流程（Steps）                                       | 用户需完成上一步配置后，才可进入下一步。当返回上一步并修改内容会影响或清空下一步已配置内容时，需进行二次确认提示。           |
| 录入信息保存时存在高风险提交                            | 提交前增加二次确认对话框（Modal）                                 | 二次确认中需说明风险提交可能造成的影响，并提供“取消 / 确认”操作。该规则属于操作风险规则，不单独决定容器类型。           |


##### 双列布局使用规则

双列布局只允许出现在以下容器中：

- 880px 右侧抽屉（Drawer）；
- 80% 屏幕宽度动态抽屉（Drawer）；
- 子页面表单。

560px 对话框（Modal）和 560px 右侧抽屉（Drawer）必须使用单列布局，录入控件宽度充满右侧内容区域，不允许使用双列布局。

双列布局仅适用于简单录入组件，包括：

- 输入框（Input）；
- 数字输入框（InputNumber）；
- 选择器（Select）；
- 日期选择器（DatePicker）；
- 开关（Switch）；
- 单选框（Radio）；
- 多选框（Checkbox）。

以下内容必须独占整行展示：

- 文本域（Textarea）；
- 表格（Table）；
- 复杂复合组件；
- 条件可见区域；
- 组合录入字段；
- 大段说明内容；
- 上传（Upload）；
- 需要横向展示的配置项。

##### 任意表单场景下必须遵守的通用布局规则

- 表单项按纵向自然排列，单个表单项内部采用“左侧字段标题 + 右侧录入控件”的横向布局。
- 录入控件宽度应根据容器宽度自适应展示，不应在 560px 容器内强制设置固定宽度。
- 在 560px 对话框或 560px 右侧抽屉中，录入控件宽度充满右侧内容区域。
- 在 880px 抽屉、80% 动态抽屉或子页面中，可根据字段数量和内容复杂度使用双列布局。
- 文本域（Textarea）宽度默认充满当前表单控件区域，高度根据录入内容复杂度设置，必要时支持纵向拉伸或内部滚动。
- 表单内容容器支持纵向滚动，字段按分组自然向下延展。
- 抽屉或子页面中如存在底部操作区，底部操作区应固定展示，避免用户必须滚动到底部后才能提交。
- 表单分组与锚点定位统一遵循本节 [表单分组与锚点定位规则](#表单分组与锚点定位规则)。

##### AI 生成时的判断顺序

1. 先判断是否包含表格、复杂复合组件或大横向内容。如包含，优先使用 880px 抽屉、80% 动态抽屉或子页面。
2. 再判断是否存在明确前后依赖关系。如存在强先后依赖，使用分步流程（Steps）。
3. 再判断字段数量和组件复杂度，并按上方 [表单容器与布局选择规则](#表单容器与布局选择规则) 选择对话框、抽屉、分步流程、分区配置或子页面。
4. 再判断是否存在条件可见字段。轻度字段依赖使用条件可见，不强制拆成分步流程。
5. 最后判断是否存在高风险提交。如存在，提交前增加二次确认对话框（Modal），说明影响范围和风险后果。

#### 字段标题区域要求


| 状态   | 要求                                                                                   |
| ---- | ------------------------------------------------------------------------------------ |
| 默认   | 字段标题字号为 14px，字重为 400，颜色使用 `gray-8`；文案应清晰准确，最长不超过 10 个字。                                           |
| 必填   | 在字段标题文本前展示红色星号，颜色使用 `Red-6`。                                                         |
| 补充信息 | 在字段标题文本后展示注解图标，图标颜色使用 `gray-7`，尺寸为 `14px × 14px`；悬停字段标题或注解图标时，使用文字提示（Tooltip）展示说明内容。 |


- 字段标题区域整体右对齐，字段标题后不要加冒号。
- 字段标题宽度在同一表单区域内保持统一，可按当前分组内最长字段标题设置统一宽度。
- 字段标题应设置最大宽度，避免过长标题挤压右侧录入控件。字段标题超过最大宽度时，应使用缩写，并配合文字提示（Tooltip）展示完整内容。
- 字段标题区域内元素间距统一为 `4px`。
- 字段标题组合展示顺序为：`必填星号 - 字段标题文本 - 注解图标`。
- 当不存在必填或补充信息时，对应元素不展示，剩余元素顺序不变。
- 字段标题组合与右侧录入控件之间的横向间距为 `16px`。

#### 录入控件状态要求


| 状态      | 要求                                |
| ------- | --------------------------------- |
| 默认      | 使用对应组件的默认录入状态。                    |
| 聚焦      | 录入控件进入聚焦状态时，应展示明确的 focus ring。    |
| 错误      | 字段校验失败时，在录入控件下方展示明确错误原因。          |
| 禁用      | 使用对应组件的禁用状态，不允许用户修改。              |
| 只读      | 使用对应组件的录入完成并禁用状态，用于展示已配置但不可编辑的信息。 |
| Loading | 提交、异步校验或数据加载期间展示加载状态，防止重复操作。      |


- 错误提示展示在对应录入控件下方，不展示在字段标题区域。
- 错误提示文案应说明具体原因，避免只提示“格式错误”“不能为空”等模糊表达。
- 同一字段同时存在说明信息和错误信息时，错误信息优先展示。

#### 校验与联动要求


| 类型     | 要求                                     |
| ------ | -------------------------------------- |
| 必填校验   | 必填项为空时，应提示具体字段及缺失原因。                   |
| 格式校验   | IP、端口、邮箱、URL、正则表达式等格式类字段，应给出明确格式要求或示例。 |
| 提交校验   | 提交时如存在错误，应自动定位到第一个错误字段，并展示对应错误原因。      |
| 异步校验   | 异步校验期间应展示校验中状态，校验完成后明确展示成功或失败结果。       |
| 条件联动   | 条件字段变化后，可根据业务规则显示、隐藏、禁用或刷新后续字段。        |
| 隐藏字段处理 | 被隐藏字段的校验和提交逻辑应与当前可见业务规则一致，不应提交无效或过期数据。 |


- 条件字段变化影响后续已填写内容时，应根据影响程度决定是否清空、保留或提示用户确认。
- 若修改当前字段会导致后续字段内容失效，应在变更前或提交前给出明确提示。
- 表单页应对当前表单内全部必填项和格式规则进行全局校验。必填项未填写、格式校验未通过或存在其他阻断性错误时，`保存` 按钮保持 disabled 状态；全部必填项填写完整且格式等校验通过后，`保存` 按钮恢复可用。
- 保存失败时应保留用户已填写内容，避免用户重复录入。

#### 提交与反馈要求


| 场景      | 要求                                              |
| ------- | ----------------------------------------------- |
| 保存成功    | 使用全局提示（Message），提示“xxx 成功”，3 秒后自动消失。            |
| 保存失败    | 使用通知提醒框（Notification），说明失败原因；通知不自动消失，需用户手动关闭。   |
| 高风险配置提交 | 保存前使用二次确认对话框（Modal），说明影响范围和风险后果，并提供“取消 / 确认”操作。 |
| 重复提交防护  | 提交过程中按钮进入 Loading 状态，避免重复点击和重复提交。               |


- 表单提交中的高风险配置包括停用、禁用、覆盖、清空、批量修改、影响业务运行或可能造成配置失效的操作。删除、还原、处置完成及其他不可恢复操作统一遵循 [8.6 Confirm](#86-confirm)。
- 保存失败后应保留当前录入内容，并允许用户修改后重新提交。

#### 抽屉表单要求

- 抽屉默认从右侧滑出。
- 点击抽屉以外的蒙层区域应触发关闭抽屉的操作。
- 抽屉宽度按 [2.3 对话框与抽屉](#23-对话框与抽屉) 的宽度判定规则选择：常规录入优先使用 560px；包含普通表格、少量复合组件或需要中等横向空间时使用 880px；表格列较多、关联内容较多或需要多区域展示时使用 80% 屏幕宽度动态抽屉。
- 标题固定顶部，操作区固定底部，内容区可滚动。
- 抽屉底部操作按钮统一靠右对齐，按钮间距使用 8px；取消等次要操作位于左侧，保存、确认等主要操作位于最右侧。
- 关闭或取消时，如存在未保存内容，应弹出二次确认。
- 配置表单中，如用户已有配置操作但尚未保存，触发关闭抽屉、点击取消、返回、切换页面、切换标签页（Tabs）或其他离开当前编辑上下文的操作时，应使用对话框（Modal）进行二次拦截；具体确认规则和文案见 [8.6 Confirm](#86-confirm)。
- 点击二次确认中的取消操作后停留在当前页面、抽屉或表单上下文，并保留用户已填写内容；点击确认操作后允许离开，并按业务规则丢弃未保存内容。
- 多步骤复杂流程优先使用独立页面或分步流程页。

#### 表单分组与锚点定位规则

- 表单默认不强制使用分组。当录入内容较少、字段都属于同一业务配置目标时，应直接纵向排列字段，不额外增加分组标题。
- 当表单内容较多，或字段可明显归属于不同业务配置维度时，可增加分组结构。
- 表单最多支持 2 级分组，避免层级过深导致用户理解成本增加。
- 表单分组层级、标题样式和垂直间距按下表执行：

| 表单结构 | 一级分组标题 | 二级分组标题 | 字段标题 | 垂直间距 |
|---|---|---|---|---|
| 不分组 | — | — | 字号 14px，字重 400，颜色使用 `gray-8` | 字段或内容块之间为 20px |
| 只有一层分组 | — | 字号 14px，字重 500，颜色使用 `gray-9` | 字号 14px，字重 400，颜色使用 `gray-8` | 分组之间为 32px；同一分组内字段或内容块之间为 20px |
| 两层分组 | 字号 16px，字重 500，颜色使用 `gray-9` | 字号 14px，字重 500，颜色使用 `gray-9` | 字号 14px，字重 400，颜色使用 `gray-8` | 一级分组之间为 40px；二级分组之间为 32px；同一分组内字段或内容块之间为 20px |

- 只有一层分组时，该分组按照二级分组样式展示。
- 两层分组中，一级分组用于承载较大的业务配置模块，二级分组用于区分具体配置内容或配置对象。
- 分组应按照业务含义组织，不应仅按字段数量机械拆分。
- 同一分组内字段应围绕同一配置目标展开，避免无关字段混排。
- 分组数量大于 3 个，或表单内容较长并超过一屏时，应提供靠右对齐的纵向 Tabs 作为锚点定位。
- 纵向 Tabs 锚点用于快速定位主要分组，不用于切换隐藏内容。
- 点击锚点后页面滚动定位到对应分组，当前所在分组对应锚点需高亮展示。
- 锚点优先对应当前表单中最高层级的分组；仅有一层分组时，锚点对应当前分组标题。

#### 操作要求

- 主要按钮文案按场景使用 `保存`、`提交`、`确认`。
- 取消按钮与主要按钮层级清晰。
- 提交期间主要按钮展示 Loading 状态并禁用重复点击。
- 保存成功后按业务返回、关闭抽屉或停留当前页。
- 保存失败后说明失败原因，并保留当前输入。

#### 结果要求

- 表单类型明确：新增、编辑、配置、提交或审批。
- 字段按业务含义分组，字段标题宽度和控件宽度统一。
- 必填、错误、禁用、只读、Loading 状态可识别。
- 如存在字段联动，联动操作应可用并有明确反馈。
- 提交成功、提交失败和未保存确认反馈完整。
- 高风险配置有影响说明和二次确认。

### 7.3 详情页

#### 页面目标

详情页用于展示单个对象的完整信息、当前状态、关联数据和可执行操作。详情页应帮助用户快速判断对象状态，并完成查看、编辑、处置、导出、审批等后续动作。

#### 推荐结构

```text
→ 抽屉标题区
   → 左侧：标题
   → 右侧：上一条 / 下一条 / 关闭
→ 抽屉内容区
   → 摘要区
      → 左侧：摘要标题
      → 右侧：主要业务操作（根据操作权重使用按钮）
   → 信息分组
   → 关联列表 / 操作记录
```

#### 布局要求

- 摘要区展示对象名称、关键状态、风险等级、核心指标和主要操作。
- 信息分组按业务语义组织，如基础信息、配置详情、风险信息、关联资源、操作记录。
- 分组标题使用模块标题样式，分组之间垂直间距为 20px。
- 关联列表应遵循列表页表格规则，保持表头、分页、状态和操作反馈。
- 详情信息字段较多时，可使用左右两列或分组布局；关键字段优先展示在上方。

#### 色彩与状态要求

- 对象等级、风险、状态、结果应使用语义色规则。
- 同一对象的状态在摘要区、详情字段、关联列表和弹层中保持相同语义。
- 状态标签数量应控制视觉噪音，最高优先级风险等级使用实色语义标签，其余风险等级使用浅色语义标签，执行状态可使用图标语义标签，需要弱化时才使用状态点语义标签。

#### 交互要求

- 详情抽屉中，上一条、下一条、关闭等浏览控制位于抽屉标题区右侧靠右对齐；编辑、处置、禁用、导出等主要业务操作位于摘要区右侧靠右对齐，并根据操作权重选择按钮类型，从右向左依次使用主要按钮、次要按钮、辅助按钮、文字按钮。
- 详情抽屉默认不设置底部操作区。
- 详情页中默认不支持编辑可使用按钮增加快捷编辑的跳转方式叠加打开录入表单对话框或抽屉，或新开浏览器/标签页进入对应的编辑页面。
- 信息分组、关联列表和操作记录按业务阅读顺序向下组织。


#### 结果要求

- 摘要区能快速识别对象和关键状态。
- 信息分组清晰，字段命名和展示顺序符合业务理解。
- 关联列表、操作记录和状态反馈完整。
- 页面操作与权限、状态和风险联动。

### 7.4 工作台 / Dashboard / 概览页

#### 页面目标

工作台用于呈现整体态势、核心指标、待办任务、风险概览、趋势变化和快捷入口。页面应帮助用户先判断全局状态，再进入具体列表或任务。

#### 推荐结构

```text
→ 核心指标区
→ 风险 / 待办 / 快捷入口
→ 图表分析区
→ 明细列表或排行
```

#### 布局要求

- 使用 12 栅格组织卡片，常见布局为 4 张或 3 张基础数据统计卡片横排。
- Dashboard 卡片常规内边距为 24px，卡片之间使用 12px / 16px / 24px，按密度选择。
- 图表类卡片应设置最小宽度，窄屏时通过换行、堆叠或页面横向滚动保持可读。
- 核心指标区应位于首屏上方，待办和风险入口应保持可点击状态。
- 工作台、Dashboard 和数据概览页的页面内容容器可纵向滚动，指标、图表、待办、排行和明细模块按栅格顺序自然向下延展。
- 页面纵向滚动时，页面内卡片按内容高度自然排列。

#### 色彩与图表要求

- 风险、状态和流程类图表先使用语义色。
- 普通分类图表使用 `c-1`–`c-20` 分类色 token，且同一分类在同一页面保持一致颜色。
- 核心数值可使用 600 / 700 字重，辅助文字使用 12px / 20px 或 14px / 22px。
- 图例应与图形颜色一致，悬停时展示完整分类、数量和占比。
- 基础数据统计卡片中的风险、状态和流程数据应与表格、详情和图表保持同一颜色语义。

#### 交互要求

- 基础数据统计卡片可点击时，应有轻量 hover 反馈，并明确跳转目标。
- 图表支持悬停查看数据详情。
- 待办、风险、排行、列表项应支持进入明细。
- 刷新、筛选、时间范围切换应同步影响对应图表和指标。
- 基础数据统计卡片 Loading、empty 和刷新反馈应与所在页面的数据刷新规则一致。
- Dashboard / 概览页中的基础数据统计卡片可作为核心业务入口，整张卡片可点击。
- Dashboard / 概览页中的基础数据统计卡片不参与筛选逻辑，点击后打开对应业务入口。
- Dashboard / 概览页跳转模式中，Hover 时仅强化主数值颜色为 `p6`，不改变整体卡片结构。
- Dashboard / 概览页跳转模式不支持选中态，不用于普通列表页筛选项。
- Dashboard / 概览页中的基础数据统计卡片图标遵循 [6.7 卡片（Card）：基础数据统计卡片与统计卡片区](#67-卡片card基础数据统计卡片与统计卡片区) 的图标规范。

#### 结果要求

- 核心指标、趋势、待办和风险入口层级清晰。
- 图表用色符合业务语义。
- 卡片栅格和响应式布局稳定。
- 点击入口、筛选联动和数据状态应完整可用。

### 7.5 分步流程页

#### 页面目标

分步流程页用于复杂配置、审批流、导入向导、策略创建和多阶段提交。页面应让用户清楚知道当前步骤、已完成内容、下一步要求和提交结果。

#### 推荐结构

```text
→ 内容容器
   → 分步流程业务容器
      → 步骤导航
      → 当前步骤内容
      → 底部操作区
```

#### 布局要求

- 步骤导航位于内容上方，展示当前步骤、已完成步骤和后续步骤。
- 当前步骤内容使用 `gray-1` 业务容器，按表单、表格、配置项或预览内容组织。
- 底部操作区保持稳定，包含 `上一步`、`下一步`、`保存`、`提交` 等操作。
- 步骤内容较多时，内容区可滚动，操作区保持可见。

#### 交互要求

- 点击下一步前应完成当前步骤校验。
- 上一步应保留已填写内容。
- 条件步骤应根据用户选择显示或跳过，并保持步骤状态清晰。
- 最终提交前应展示确认信息或影响范围。
- 提交成功和失败都应给出明确反馈。

#### 结果要求

- 步骤数量、当前步骤和完成状态清晰。
- 每一步的输入、校验、保存和返回行为稳定。
- 最终提交前有确认信息，提交后有结果反馈。

### 7.6 异常页 / 空状态页

#### 页面目标

异常页和空状态页用于解释当前页面无法展示数据或任务无法继续的原因，并提供下一步动作。

#### 推荐结构

```text
状态图标 / 插图
→ 状态标题
→ 原因说明
→ 下一步操作
```

#### 状态要求


| 状态    | 要求                         |
| ----- | -------------------------- |
| 初始无数据 | 文案使用 `暂无数据`，可提供新建、导入或配置入口  |
| 搜索无结果 | 文案使用 `暂无匹配数据，请调整筛选条件`      |
| 加载失败  | 说明失败原因，并提供重试入口             |
| 无权限   | 说明当前权限状态，并提供申请权限、切换账号或返回入口 |
| 网络异常  | 说明连接异常，并提供重试或刷新入口          |


#### 设计要求

- 空状态应放在当前内容区域内，保持页面结构稳定。
- 列表空状态应保留表头，在表格内容区展示提示。
- 异常说明应表达发生了什么、影响了什么、下一步能做什么。
- 主要动作使用主要按钮，次要动作使用辅助按钮或文字按钮。

#### 结果要求

- 状态标题、原因说明和下一步动作完整。
- 空状态和异常状态没有破坏页面框架。
- 重试、返回、新建、申请权限等动作可明确识别。

### 7.7 图标密集页 / 菜单配置页 / 图标按钮页

#### 页面目标

图标密集页用于菜单配置、权限配置、工具入口、图标按钮组合和低频辅助操作。页面应保证图标含义清晰、尺寸统一、状态明确。

#### 布局要求

- 图标尺寸、按钮尺寸、间距和对齐方式应统一。
- 图标按钮建议使用 32px × 32px 尺寸。
- 同一工具组内，图标按钮间距使用 8px。
- 图标与文字组合时，图标与文字间距使用 4px 或 8px。

#### 交互要求

- 使用仅图标内容组合的按钮时，应提供文字提示（Tooltip）或 aria-label。
- 可点击图标应有 hover、focus、active 和 disabled 状态。
- 当前选中图标应使用品牌主色或浅主色背景表达。
- 删除、停用、覆盖等高风险图标操作应保留文字说明或确认机制。

#### 结果要求

- 图标含义可理解，低频图标有说明。
- 图标按钮尺寸、对齐和状态统一。
- 图标颜色遵循品牌色、语义色和中性色规则。

## 8. 交互状态与反馈规范

### 8.1 权限状态


| 状态   | 使用场景               | 要求                          |
| ---- | ------------------ | --------------------------- |
| 正常显示 | 用户有权限操作            | 操作入口可见且可点击                  |
| 禁用显示 | 用户需要知道能力存在，但当前条件不足 | 操作入口保留，显示 disabled 状态，并说明原因 |
| 隐藏   | 用户完全无查看权限或能力对其无意义  | 操作入口从当前界面移除                 |


### 8.2 Loading

- 异步请求应展示 Loading。
- 表单提交 Loading 期间，主要按钮应进入加载态并防止重复提交。
- 超过 2 秒的任务建议说明当前阶段。
- 其他操作如无法及时反馈，应按操作范围给出对应 Loading 状态，避免用户重复点击或误判系统无响应。
- 列表刷新 Loading 应替换表格内容区，表头保持稳定。
- 数据恢复后，Loading 状态应回到正常内容状态。

### 8.3 Empty

- 空状态应说明没有数据的原因，并提供下一步动作。
- 初始无数据使用 `暂无数据`。
- 搜索无结果使用 `暂无匹配数据，请调整筛选条件`。
- 列表空状态应保留表头，隐藏分页区。

### 8.4 Error

- 异常状态应说明发生了什么、影响了什么、下一步能做什么。
- 加载失败应提供重试入口。
- 保存失败应说明失败原因，并保留用户输入。
- 表格加载失败时，表头保持稳定，表格内容区展示错误原因和重试入口。

### 8.5 Success / Failure

- 操作成功应使用全局提示（Message）反馈，并按业务刷新页面、关闭弹层或停留当前页。
- 操作失败应说明原因，并保留当前上下文。
- 批量操作成功或失败后，应刷新相关数据并反馈结果。
- 所有操作完成后均应给出反馈，不应存在无反馈操作。
- 操作成功默认使用全局提示（Message），文案为 `xxx 成功`，3 秒后自动消失。
- 操作失败默认使用通知提醒框（Notification），标题为 `xxx 失败`，内容示例为 `网络异常，请检查后重试`；具体通知内容以接口返回数据为准，通知提醒框（Notification）不自动消失，需用户手动关闭。
- 操作无法及时完成时，应展示对应 Loading 状态；任务完成或失败后，再切换为成功或失败反馈。

### 8.6 Confirm

以下操作应提供二次确认：

- 删除、批量删除。
- 停用、禁用、还原。
- 覆盖已有配置。
- 高风险配置保存。
- 处置完成、忽略、关闭告警等改变业务状态的操作。
- 关闭存在未保存内容的表单、对话框或抽屉。
- 配置表单已有配置操作后未保存，触发离开当前页面、关闭对话框 / 抽屉、切换页面或切换标签页（Tabs）等离开操作。
- 其他业务定义的风险操作，如删除、覆盖、清空、重置、停用、禁用、批量处置或不可恢复操作。

确认对话框应包含明确标题、影响说明、主操作和取消操作。

二次确认统一使用对话框（Modal）。未保存离开拦截示例：标题为 `确定离开当前页面么？`；内容为 `离开后，数据将不会被保存，请谨慎操作`；操作项为 `取消` / `确定`。

风险操作拦截示例：标题为 `确定删除xxxx么？`；内容为 `删除后，将无法恢复，请谨慎操作`；操作项为 `取消` / `确定`。其中 `xxxx` 在单条删除时用`该项`，批量删除时用`所选`

### 8.7 Disabled

禁用状态应满足以下要求：

- 禁用按钮视觉上降低对比度，并保持可识别。
- 禁用原因较复杂时，通过文字提示（Tooltip）或辅助说明解释。
- 禁用状态与 Loading 状态视觉区分清晰。
- 权限不足、条件不足、数据缺失、状态锁定等原因应有对应说明。

## 9. 设计输出要求

### 9.1 页面交付内容

设计输出应包含以下内容：


| 输出项      | 要求                                                                             |
| -------- | ------------------------------------------------------------------------------ |
| 完整业务内容框架 | 内容容器和业务容器完整，业务内容层级清晰 |
| 页面类型说明   | 标明页面属于列表、表单、详情、工作台、分步流程、异常页或图标密集页                                              |
| 主要业务状态   | 默认、Loading、empty、error、success、disabled、confirm 等状态覆盖                          |
| 关键交互说明   | 搜索、清空、排序、筛选、分页、提交、取消、确认、展开收起等交互明确                                              |
| 响应式说明    | 说明 1920px、1440px、1366px、1280px 和窄屏下的布局策略                                       |
| 组件状态     | 按钮、输入框、选择器、表格、标签、对话框、抽屉等组件状态完整                                                 |
| 语义色说明    | 风险、状态、流程、图表色按业务语义标注 token，不写具体色值                                               |
| 资源来源说明   | 图标、图片和切图资源来源明确；资源缺失时说明生成边界。                                     |
| 页面要求汇总   | 页面关键规则和例外说明完整                                                    |


### 9.2 标注要求

- 页面应标注关键容器尺寸、内边距、模块间距和按钮间距。
- 表格应标注行高、表头样式、固定列、分页区和状态区域。
- 表单应标注字段标题宽度、控件宽度、字段间距、错误提示和说明文案位置。
- 图表应标注颜色 token、图例位置、悬停信息和空状态。
- 对话框和抽屉应标注宽度、标题区、内容区、底部操作区和滚动区域。

### 9.3 交付质量要求

- 页面应使用稳定后台框架。
- 内容容器和业务容器层级应清晰。
- 间距应遵循 4px 原子单位和统一间距表。
- 字号、行高、字重应符合排版规范。
- 主色、状态色、风险色和图表色应符合语义 token 规则。
- 同类组件在同一页面和跨页面中应保持一致。
- 关键操作应有明确反馈。
- 高风险操作应有确认机制。
- 空状态、异常状态、加载状态和禁用状态应完整。
- 响应式和滚动策略应保证核心信息可读、关键操作可见。
- 每个页面类型的结果要求应全部覆盖。
